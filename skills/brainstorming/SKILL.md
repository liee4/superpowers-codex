# Brainstorming

1. Read the request, related code, and existing constraints. Use the project's terminology and established defaults.
2. Identify the decision that would change the implementation or outcome. If the request already settles it, proceed. For a reversible implementation choice, use the project default or state a reasonable assumption and continue.
3. If a material decision remains and local evidence cannot resolve it, ask one focused question. Describe the realistic options, their consequences, and your recommendation when useful. Continue work that does not depend on the answer.
4. Once the decision is clear, carry out the authorized work. Record a durable design document if requested or needed for review or handoff. Cover the affected behavior, interfaces, compatibility, and validation as relevant.
5. Use [writing-plans](../writing-plans/SKILL.md) when sequencing or handoff warrants a plan.
